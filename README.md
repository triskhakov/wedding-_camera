# Свадебная камера

Внешний вид страницы сохранён. Снимок отправляется в Telegram-группу; приложение не записывает фотографии на диск компьютера или в постоянное хранилище браузера. Для безопасной отправки нужен небольшой сервер Node.js 22 или новее, который скрывает токен от посетителей. Внешних npm-зависимостей нет.

## Запуск

1. В Telegram откройте [@BotFather](https://t.me/BotFather), отправьте `/revoke` и выберите `@weddingsave_bot`. Старый токен был опубликован в исходниках: удаление из HTML не отзывает его.
2. Скопируйте `.env.example` в `.env` рядом с `server.mjs`.
3. В `.env` заполните `TELEGRAM_BOT_TOKEN` новым токеном, `TELEGRAM_CHAT_ID` идентификатором закрытой группы и `ADMIN_PIN` своим ПИН-кодом (до 6 символов, как в существующей форме). У бота должно быть право отправки документов в эту группу. Не публикуйте `.env`.
4. Из этой папки выполните:

   ```sh
   node --env-file=.env server.mjs
   ```

5. Откройте `http://localhost:3000`. Если токен и чат не настроены, сервер намеренно запрещает загрузки. Без `ADMIN_PIN` вход организаторов запрещён.

Для автоматических проверок:

```sh
node --test test/*.test.mjs
```

Тесты используют подменённый Telegram API, реальных сообщений не отправляют.

## Размещение

Размещайте страницу и API на одном домене за HTTPS. Укажите `NODE_ENV=production`, `PUBLIC_ORIGIN=https://ваш-домен` без пути и настройте HTTPS reverse proxy на сервер Node.js. Для запуска в контейнере может понадобиться `HOST=0.0.0.0`. Обычный GitHub Pages не исполняет Node.js: только публикации HTML теперь недостаточно.

Запускайте **один процесс сервера** с постоянным диском для `data/uploads.json`. Не запускайте несколько экземпляров, использующих этот файл. Он хранит сессии и результаты загрузок; его удаление сбросит лимиты и защиту от повторов. Для serverless или нескольких процессов потребуется общее транзакционное хранилище — текущая версия рассчитана на один небольшой сервер.

`TRUST_PROXY=1` включайте только за собственным proxy, который перезаписывает `X-Forwarded-For`, и закройте прямой доступ к Node.js из интернета. Иначе клиент сможет подменять IP для ограничений. По умолчанию заголовку proxy сервер не доверяет; за proxy без этой настройки все гости будут иметь общий IP.

## Что изменилось

- Токена Telegram и допустимых ПИН-кодов в HTML больше нет. ПИН проверяется сервером с ограничением попыток.
- Гость отправляет JPEG на `/api/photos`; сервер проверяет запрос и отправляет один документ в Telegram. Отдельной дублирующей отправки `sendPhoto` нет. Как и раньше, это фото после обработки canvas и добавления подписи, а не исходный файл камеры.
- Имя гостя не вставляется в HTML или JavaScript-обработчики: карточки строятся через DOM API.
- Фотографии находятся только в оперативной памяти открытой вкладки для отправки и существующего предпросмотра. IndexedDB и localStorage для фотографий не используются. Сервер передаёт файл в Telegram без записи изображения на диск; в `data/uploads.json` хранятся только служебные сведения о сессиях и доставке.
- Успех показывается только после подтверждения Telegram. Неотправленные снимки можно повторить при восстановлении связи, пока вкладка открыта, с тем же ID. При закрытии или перезагрузке вкладки они исчезают. Снимки с неизвестным результатом автоматически не повторяются.
- Сессия гостя хранится в HttpOnly cookie. Лимит 15 кадров проверяется сервером; также ограничены частота, размер файлов и общее число загрузок мероприятия.

## Ограничения, которые важно учитывать

**Постоянный архив находится в Telegram.** Существующие галерея и ZIP-кнопка работают только со снимками в памяти текущей открытой вкладки; автоматической записи на компьютер нет. Скачивание ZIP происходит только по нажатию пользователя. Названия, кнопки и компоновка оставлены по просьбе владельца. Серверный вход по ПИН не превращает настройки и ZIP в защищённый общий веб-архив: таких API в этой версии нет.

Лимит 15 кадров относится к сессии, а не к подтверждённой личности. После удаления cookie можно получить новую сессию в пределах ограничений сети. Строгое ограничение на человека требует индивидуальных приглашений. Лимит новых сессий на IP следует подбирать с учётом общего Wi-Fi и мобильных сетей.

Если сервер потерял подтверждение Telegram, запись получает статус `unknown`. Идентификатор снимка указан в имени документа и подписи в Telegram. Организатор должен проверить наличие документа. **Не удаляйте запись и не присваивайте новый ID ради повторной отправки:** это может создать дубликат. Автоматического разрешения неопределённых отправок и панели восстановления пока нет; снимок доступен в памяти, только пока вкладка открыта.

Старые записи фотографий, если они остались от прежних версий в хранилище браузера, новая версия не читает и не изменяет. Настройки и имя гостя могут храниться в localStorage; изображения туда не записываются. Постоянное хранение файлов выполняет Telegram.

Для настройки доступны `DATA_FILE`, `MAX_UPLOAD_BYTES`, `MAX_CONCURRENT_UPLOADS`, `EVENT_UPLOAD_CAP`, `TELEGRAM_TIMEOUT_MS`, `SESSIONS_PER_IP_PER_DAY`, `MAX_SESSIONS`. Значения по умолчанию смотрите в `server.mjs`. Не увеличивайте лимит файла без согласования с клиентским пределом 10 МиБ.

Исходный ZIP в родительской папке всё ещё содержит старый токен. Это неизменённый входной архив, а не версия для публикации. Не публикуйте его или `.env`; в Git отправляйте только содержимое этой папки с учётом `.gitignore`.
